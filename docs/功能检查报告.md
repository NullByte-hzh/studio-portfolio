## 结论摘要

网站主体功能（首页轮播、深色模式、作品筛选、灯箱、缩放、全屏、幻灯片、地图标记、预约表单、上传、Service Worker 离线）均能正常工作。发现 **4 个严重问题、2 个中等问题、若干轻微问题**，详见下文。

## 一、严重问题（功能不可用或实际失效）

### 1. Decap CMS 管理后台无法打开（配置不兼容 Decap 3.x）

访问 `/admin/` 时页面显示：

```
Error loading the CMS configuration
Config Errors:
config must have required property 'media_folder'
config must have required property 'media_library'
config must match a schema in anyOf
'collections[1].files[0]' must have required property 'name'
```

原因（`admin/config.yml`）：
- 配置里用的 `media:` 块（`output_path` / `public_folder`）不符合 Decap 3.x schema，schema 要求顶层必须有 `media_folder` 或 `media_library`（`anyOf`）。
- `pages` 集合的 files 条目缺少必填的 `name` 字段。

已在本地用 Decap 3.1.x 实测验证，以下修正可让后台正常加载（显示 GitHub 登录页，无配置报错）：

```yaml
media_folder: 'uploads'
public_folder: '/uploads'
# 删除原来的 media: 块和 media_library 块
...
collections:
  - name: 'pages'
    files:
      - name: 'home'        # 新增
        label: '首页'
        file: 'index.md'
        ...
```

### 2. CMS 与网站数据脱节（修好配置后也无法真正管理作品）

- CMS 的 `gallery` 集合把作品写入 `_gallery/*.md`，但网站画廊数据是硬编码在 `index.html` 的 `galleryData` 数组里，CMS 新增/修改/删除的作品**不会出现在网站上**。
- CMS 的 `pages` 集合指向 `index.md`，但网站是静态 `index.html`，不会读取 `index.md`，编辑首页内容同样不生效。
- 仓库中目前也没有 `_gallery/` 目录和 `index.md` 文件。

要让 CMS 真正可用，需要把网站改为从 `_gallery/` 加载作品数据（或移除 CMS 的画廊/页面集合）。

### 4. 地图底图无法加载（OpenStreetMap 瓦片在当前网络不可用）

地图功能本身正常：Leaflet 加载成功、3 个地点标记、弹窗可打开。但底图瓦片（`tile.openstreetmap.org`）在本地和线上实测均大量失败（`ERR_CONNECTION_RESET` / `ERR_TIMED_OUT`，线上 24/24 瓦片加载失败），地图实际显示为灰底 + 标记。对位于中国大陆的用户这是常见问题，建议更换为国内可访问的瓦片源（高德、腾讯、GeoQ）或增加备用源。

## 二、中等问题

### 5. 线上子路径部署（GitHub Pages 项目页）的路径问题

站点部署在 `https://NullByte-hzh.github.io/studio-portfolio/`（子路径），但部分路径写死为根路径：

- `manifest.json` 中 `start_url: "/"`、`scope: "/"` → 安装 PWA 后打开的是仓库根目录（404），PWA 安装体验损坏。
- `index.html` 页脚「管理」链接 `href="/admin/"` → 线上点击会跳到 `https://NullByte-hzh.github.io/admin/`（404），应改为相对路径 `admin/`。
- `service-worker.js` 缓存清单 `ASSETS` 使用绝对路径（`'/'`、`'/index.html'` 等）→ 线上安装时这些缓存全部失败（靠 `allSettled` 不中断安装）。实测线上离线访问仍可用，是因为导航请求本身会被缓存，但 manifest/icon 等不会被预缓存。

### 6. 「我的上传」筛选逻辑错误

`getAllItems()` 中 `uploaded` 分支会把内置 16 张作品和上传照片一起返回。实测点击「我的上传」后显示 17 项（16 张内置 + 1 张上传），而不是只显示上传的照片；删除上传照片后仍显示 16 张内置作品。应改为 `uploaded` 只返回 `uploadedPhotos`。

## 八、管理后台登录修复（2026-08-10）

用户反馈管理后台点击「Login with GitHub」后出现 `404 Not Found`（`api.github.com` 返回的 JSON）。经核实根因：

`admin/config.yml` 中配置了 `base_url: https://api.github.com` 和 `auth_endpoint: https://github.com/login/oauth/authorize`。Decap CMS 3.x 的 GitHub 后端把这两项拼接成「自定义 OAuth 服务器地址」（`https://api.github.com` + `/` + `https://github.com/login/oauth/authorize`），拼出无效路径，导致授权窗口在 `api.github.com` 上 404。

修复：删除这两行，使用 Decap 官方默认的 Netlify OAuth 网关：

```yaml
backend:
  name: github
  repo: NullByte-hzh/studio-portfolio
  branch: main
```

已提交并推送（commit `1528666`），线上验证：

- 线上授权弹窗 URL 为 `https://api.netlify.com/auth?provider=github&site_id=nullbyte-hzh.github.io&scope=repo`（官方网关，会正确跳转 GitHub 授权页）
- 仓库、GitHub API、线上 Pages 三处配置均已确认不含 `base_url`/`auth_endpoint`
